# @checkout/web

Фронтенд магазина: каталог, корзина, оформление, оплата тестовой картой или наличными.

## Запуск

Нужны Node.js 24.x и npm 11.x. Команды — из корня репозитория.

```sh
npm ci
npm run dev
```

- фронт: http://127.0.0.1:5173
- API: http://127.0.0.1:4000 (`/docs`)
- Vite проксирует `/api` на API

Адрес API задаётся в `apps/web/.env` (`VITE_API_URL`). Скопируйте `apps/web/.env.example`. Для локального `npm run dev` хватает `VITE_API_URL=/api`. Чтобы ходить в API напрямую: `VITE_API_URL=http://127.0.0.1:4000/api`.

Отдельно:

```sh
npm run dev:web     # только Vite, нужен API на :4000
npm run build:web   # tsc --noEmit и сборка
npm run lint        # eslint @checkout/web
npm run generate:sprites -w @checkout/web
```

Тестовые контакты: имя любое от 2 символов, `buyer@example.test`, `+79990000000`.

## Как устроен клиент

Все HTTP-запросы идут через `shared/api` (`instance` на `fetch`). Там же: базовый URL, заголовки, `Authorization`, `Idempotency-Key`, разбор конверта `{ data }` / `{ error }`, 204 без `json()`. HTTP, сеть и битый JSON сводятся к `ApiClientError`; отмена запроса (`AbortError`) не оборачивается. 401 → новая сессия и повтор, 5xx → alert. Страницы не видят `Response` и не проверяют `ok`.

Слои (тонкий FSD):

| Слой       | Ответственность                                                         |
| ---------- | ----------------------------------------------------------------------- |
| `app`      | роутер, провайдеры                                                      |
| `pages`    | экраны и сборка сценария                                                |
| `entities` | доменные API и хуки (`product`, `cart`, `checkout`, `order`, `payment`) |
| `shared`   | клиент, конфиг, UI, форматтеры                                          |

Состояние сервера кэширует TanStack Query. Формы — react-hook-form + zod. Суммы в копейках, показ через `amountFormat`. Итог и доставка только из quote/заказа, не считаются на клиенте.

## Обработка данных

Пример: количество в корзине для карточек каталога.

`useCartQuantity` один раз проходит `cart.items` и собирает `Map<productId, quantity>`. Карточки вызывают `getQuantity(id)` — это O(1), без поиска по массиву на каждый товар и без `.map().filter()` при рендере сетки. `Map` живёт, пока не сменилась ссылка на `cart`.

Тот же приём на странице корзины для `stock` по `productId`. Активную попытку оплаты ищем одним проходом `getActivePayment`, не через `filter` + `find`.

## Проверенные сценарии

- Каталог: добавление, остаток, товар без stock недоступен.
- Корзина: количество, удаление, пустое состояние, сумма с API.
- Оформление: самовывоз и курьер, quote при смене доставки, контакты, наличные и карта.
- Наличные: страница успеха, текст «Заказ оформлен, оплата при получении», данные заказа с сервера.
- Карта: название и маска из sandbox, ожидание, успех только при `order.status = paid`.
- Отказ карты и отмена: повтор того же заказа новой попыткой и новым `Idempotency-Key`.
- Двойной клик оформления и оплаты: тот же ключ и тело.
- Пустая корзина не оформляется (редирект на `/cart`).
- Перезагрузка: сессия из `localStorage`, корзина с API, незавершённая оплата продолжает опрос на `/orders/:id/payment`.
- Вёрстка: основные поля и кнопки доступны при 1280 и 390 px.

## Решения

- После создания заказа `checkout/options` не инвалидируем на чекауте — иначе пустая корзина уводит на `/cart` раньше редиректа.
- Опрос оплаты: TanStack Query `refetchInterval` 500 мс, `AbortSignal` на запросе, стоп при терминальном статусе, фоне и размонтировании.

## Недоработки

- Пункт выдачи на успехе показывается как «Самовывоз», без названия ПВЗ (в заказе только `pickupPointId`).
- Неоплаченный заказ с главной сам не открывается: нужен URL `/orders/:id` или `/orders/:id/payment`.
- Заголовок `Retry-After` у 202 не читаем: интервал опроса фиксированный 500 мс (в диапазоне задания).
- Нет e2e на UI; HTTP-сценарии API — `npm run smoke` из корня.
